Mobile admin rule

Mobile is for quick checks and emergency action, not full catalogue work.

  • Show only urgent counts and top queue items.
  • Keep payment review and shipping actions reachable.
  • Push full product editing back to desktop.

Responsive behavior

Tables become priority cards; filters remain horizontal and scroll-safe.

  • Dashboard metrics collapse to two columns.
  • Order detail stacks customer, items, payment, and delivery.
  • Settings cards stack by market.

Phase 1 boundary

Admin mobile support is valuable, but storefront mobile remains the launch-critical responsive path.

  • Desktop admin first.
  • Mobile admin as stretch if time allows.
  • No roles or advanced analytics in Phase 1.
